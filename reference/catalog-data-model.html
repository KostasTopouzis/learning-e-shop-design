Catalog data model

Product = what you browse. Variant = what you buy.

From: Lesson 0001Updated 2026-10-25

The three concepts

EntityIsHolds
ProductThe shared description of a family of itemstitle, description, handle (slug), brand, material, care, shared images
Option + valuesA choice the customer makesname ('Size'), position; values ('S','M','L')
VariantOne purchasable combination of option values. The unit of salesku, barcode, price, stock, weight

Rules of thumb

  • The "differs per combination?" test: if a value can differ between Navy/M and White/L, it belongs on the variant.
  • Cart lines, order lines and inventory always reference a variant, never a product.Saleor
  • Every product has at least one variant. A product with no options gets one default variant.Shopify
  • Variant count = product of option sizes (3 colours × 4 sizes = 12). It grows fast. Shopify caps it at 2,048 per product.
  • No two variants of a product may share the same option values.

Schema (Postgres)

products               (id, handle UNIQUE, title, description, brand, created_at)
product_options        (id, product_id → products, name, position, UNIQUE(product_id, name))
product_option_values  (id, option_id → product_options, value, UNIQUE(option_id, value))
product_variants       (id, product_id → products, sku UNIQUE,
                        price_cents int CHECK ≥ 0, stock int CHECK ≥ 0)
variant_option_values  (variant_id → variants, option_value_id → option_values,
                        PK(variant_id, option_value_id))
