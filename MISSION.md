# Mission: E-commerce system design for web developers

## Why
Get hired as a web/software engineer by turning "The Edit" (a React storefront deployed on Vercel) into a professional-grade, full-stack Next.js + Postgres e-shop. I want to be able to explain, and defend in interviews, how a real commerce platform is designed: its data model, its subsystems and how data flows between them, and how the business behind it operates.

## Success looks like
- I've designed and implemented a Postgres data model for The Edit (catalog, variants, inventory, cart, orders, customers) and can justify every table and constraint.
- Product listing/search, product detail, cart and checkout work end-to-end in Next.js against that database.
- I can draw The Edit's subsystems (catalog, cart, checkout, payments, orders, inventory, accounts) and walk through the data flow of "add to cart → pay → order fulfilled", including failure cases.
- I understand the business side well enough to model it: pricing, stock, returns/refunds, order lifecycle.
- I can answer common e-commerce system-design interview questions using The Edit as my worked example.

## Constraints
- ~3–5 hours/week, in short focused sessions.
- Stack: Next.js (migrating from plain React), Postgres, deployed on Vercel, own GitHub repo.
- Current level: can build simple full-stack apps (UI + API + DB) and deploy. Now needs professional depth.

## Out of scope
- Platform comparisons (Shopify vs WooCommerce etc.).
